### 1. O que são "Entidades" e "Propriedades"?

No nosso código C#, quando você cria uma classe que vira uma tabela no banco de dados (por exemplo, a classe `User` ou `Corporation`), nós temos duas coisas:

1. **A Entidade (`EntityDefinition`)**: É a **Ficha / Tabela inteira**.
   - Exemplo: `User` (que no banco é a tabela `sec_users`), `Corporation` (`mpx_corporations`), `Invoice` (`fin_invoices`).
2. **As Propriedades (`EntityProperty`)**: São **cada um dos campinhos (colunas ou ligações)** que existem dentro daquela classe C#!
   - Exemplo dentro da classe `User`:
     - `Name` (texto, tamanho máximo 120, obrigatório)
     - `Email` (texto, formato de e-mail, obrigatório)
     - `BirthDate` (data, opcional)
     - `CorporationId` (chave estrangeira que aponta para a entidade `Corporation`)
     - `UserRoles` (uma lista/coleção que liga o `User` aos perfis dele)

Ou seja: **"Propriedade" é simplesmente o nome que o C# dá para cada campo de uma classe.**

Por isso, com a API no ar 24/7, existem **3 lugares** onde esse ponto de partida pode morar:

1. **No próprio `App Builder` (Ao Salvar/Publicar uma Entidade ou Campo na Tela)**:
   - No instante em que o usuário (ou consultor) cria ou edita uma Entidade/Propriedade na tela do Morphus, o Handler já grava na `mpx_entities` / `mpx_entity_properties` e executa a alteração na hora, sem depender de boot da API.
2. **Sob Demanda no Endpoint / Handler de Listagem (ou Botão `"Sync Catalog"`)**:
   - Quando a tela do `App Builder` ou do `Morphus Flow` pede a lista de Entidades (`GET /api/entity-definitions` ou `POST /api/entity-definitions/sync`), ou quando o cache expira, o próprio serviço confere se há algo novo e sincroniza em tempo real com a API ligada.
3. **Na Migration / Gatilho do Banco (`EF Migration` / `DDL Trigger` no Postgres)**:
   - Toda vez que uma Migration roda no banco, ela mesma já dispara a atualização do catálogo.
