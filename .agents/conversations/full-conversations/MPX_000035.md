---

### 1. `DNSSEC` (Imagem 1 — Validação de Assinatura Digital do DNS)
* **O que é**: Garante que a resposta do DNS veio realmente do dono legítimo do domínio (validando assinaturas criptográficas) e não de um servidor falsificado no meio do caminho (_Man-in-the-Middle_ / _Cache Poisoning_).

  * Logo abaixo, você ainda tem uma ferramenta **Diagnose** para testar qualquer domínio na hora e ver se a assinatura DNSSEC dele está válida (`Verify Result`).
* **Vale ativar?** **Sim!** Basta marcar **`Enable`** e clicar em **`Save`**.

---

### 2. `DOH` — _DNS over HTTPS_ (Imagem 2) e 3. `DOT` — _DNS over TLS_ (Imagem 3)
* **O que são**: Enquanto o DNSSEC garante que a resposta **não foi adulterada**, o **DoH** e o **DoT** **criptografam o túnel inteiro** entre o seu Omada e o servidor de DNS público (Google, Cloudflare, Quad9). Nem o seu provedor de internet consegue bisbilhotar quais domínios sua rede está consultando!
* **Qual a diferença entre DoH e DoT?**
  * **DoH (`DNS over HTTPS` — Porta 443)**: Passa as consultas de DNS por dentro do protocolo HTTPS normal (igual ao tráfego de qualquer site seguro). É impossível de diferenciar de uma navegação web comum e nunca é bloqueado por operadoras.
  * **DoT (`DNS over TLS` — Porta 853)**: Usa um túnel TLS dedicado na porta 853. É um pouquinho mais leve no protocolo, mas algumas operadoras ou redes externas podem filtrar a porta 853.
* **Dica de Ouro (Como configurar)**:
  * Você não precisa ligar os dois ao mesmo tempo — **escolha um** (eu recomendo **DoH** ou **DoT** com **Cloudflare `1.1.1.1`** + **Google `8.8.8.8`** + **Quad9 `9.9.9.9`** habilitados na tabela embaixo, clicando no ícone de check na coluna `Status` para mudar de `Disabled` para `Enabled`, e depois marcando o `Enable` no topo).

---

### 4. `DNS Cache` (Imagem 4 — Já está `Enabled`!)
* **O que é**: O próprio roteador Omada guarda na memória RAM dele os IPs dos domínios que as máquinas da sua rede já consultaram.
* **Por que é excelente**: Quando uma máquina ou container seu consulta `github.com` ou `api.openai.com`, a primeira consulta vai lá fora (via DoH/DoT criptografado) e o Omada guarda no cache. Na segunda consulta (de qualquer aparelho da sua casa/escritório), o Omada responde em **menos de 1 milissegundo** direto da rede local!
* Repare que se você clicar em **`refresh`** ali na `DNS Cache Table`, ele deve listar todos os domínios que estão em cache no roteador neste exato momento (se o gateway das máquinas estiver apontando o DNS para o IP do Omada).

Aqui está o comando completo do PowerShell (colorido e atualizando a cada 1 segundo na tela), mostrando ao vivo **qual placa está ativa (`Ethernet` ou `Wi-Fi`)**, o **IP**, o **DNS (`192.168.0.1, 1.1.1.1`)** e o **Ping** para o Omada e para a Internet mientras você puxa e pluga o cabo:

```powershell
while ($true) {
    $cfg = Get-NetIPConfiguration | Where-Object { $_.IPv4DefaultGateway -ne $null } | Select-Object -First 1
    $pingOmada = Test-Connection 192.168.0.1 -Count 1 -ErrorAction SilentlyContinue
    $pingNet   = Test-Connection 1.1.1.1 -Count 1 -ErrorAction SilentlyContinue
    $hora = Get-Date -Format "HH:mm:ss"

    if ($cfg) {
        $iface = $cfg.InterfaceAlias
        $ip    = $cfg.IPv4Address.IPAddress
        $dns   = ($cfg.DnsServer.ServerAddresses | Where-Object { $_ -match '^\d+\.' }) -join ", "
        $msLan = if ($pingOmada) { "$($pingOmada.ResponseTime)ms" } else { "TIMEOUT" }
        $msWan = if ($pingNet)   { "$($pingNet.ResponseTime)ms" }   else { "TIMEOUT" }
        $cor   = if ($iface -eq "Ethernet") { "Green" } else { "Cyan" }

        Write-Host "[$hora] " -NoNewline
        Write-Host ("{0,-10}" -f $iface) -ForegroundColor $cor -NoNewline
        Write-Host " | IP: $ip | DNS: [$dns] | Omada: $msLan | Internet: $msWan"
    } else {
        Write-Host "[$hora] TRANSICAO DE REDE (Failover em andamento...)" -ForegroundColor Yellow
    }
    Start-Sleep -Seconds 1
}
```
