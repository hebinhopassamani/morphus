### 2. Segunda mágica: Descobrir o "buraco" na sequência automaticamente (`001` vago!)
Hoje o seu cálculo de `nextNum` provavelmente pega o **maior número (`max + 1`)** — então se você tem `002, 003, 004` (porque apagou o `001`), ele sugere `005` em vez de perceber que o **`001` está livre**!

Com 5 linhas de JS no seu modelo, o `nextNum` acha **o primeiro número vago da sequência** (se apagou o `001`, ele já sugere `001`; se apagou o `003`, ele sugere `003`; se não tem buraco, sugere `005`):

```javascript
// Pega todos os números já usados na pasta (ex: [2, 3, 4])
const usados = new Set(
  app.vault.getMarkdownFiles()
    .filter(f => f.parent?.path === tp.file.folder(true) && f.path !== tp.file.path(true))
    .map(f => {
      const m = f.basename.match(/^(\d{3})/);
      return m ? parseInt(m[1], 10) : null;
    })
    .filter(n => n !== null)
);

// Encontra o primeiro número livre a partir do 1 (se 1 estiver vago, retorna "001"!)
let livre = 1;
while (usados.has(livre)) livre++;
const nextNum = String(livre).padStart(3, '0');
```
Só com isso, quando você apagar a `001` e criar uma nota nova, o prompt já vai abrir sugerindo **`001`** automaticamente!

Cara, a sua observação é de uma precisão absurda! Deixa eu te explicar **exatamente** por que cada um desses fenômenos acontece nos bastidores do Markdown e do Obsidian (vai aliviar o seu TOC na hora por entender a lógica por trás!):

---

### 1. Por que o texto colado nos `---` de baixo fica GIGANTE (como um Título) no arquivo do Modelo?
Na especificação original do Markdown (chamada *Setext Heading*), qualquer linha de texto seguida imediatamente na linha de baixo por `---` é interpretada pelo Markdown como um **Título H2 (`<h2>`)**!
- Mas você pode perguntar: *"Ué, mas `---` não é o fechamento das Propriedades (YAML Frontmatter)?"*
- **Aí está o pulo do gato:** No arquivo do **Modelo**, antes das propriedades você tem o bloco de código do Templater (`<%* ... -%>`) na linha 1!
- Para o Obsidian reconhecer `--- ... ---` como uma caixa de Propriedades oficial, o primeiro `---` **tem que estar obrigatoriamente na Linha 1, Coluna 1 do arquivo**.
- Como no arquivo do Modelo a Linha 1 começa com `<%*` (código do Templater), enquanto você está olhando o arquivo do Modelo, o Obsidian acha que aquilo **ainda não é** um cabeçalho de propriedades, e sim texto normal! Aí quando ele vê:
  ```markdown
  modelo de nota: Tutorial - Descrições e Codificações
  ---
  ```
  Ele pensa: *"Opa! Um texto com `---` colado embaixo! Isso é um Título H2!"* e deixa a letra gigante!
- Já quando a **nota final é criada**, o Templater apaga o `<%* ... -%>` lá de cima, o primeiro `---` sobe para a **Linha 1**, e aí o Obsidian reconhece o bloco inteiro como Propriedades!

---

### 2. Por que quando você dá um `Enter` antes do `---` final, o texto volta ao normal e os `---` viram uma linha contínua (`___`)?
Porque no Markdown:
- **`Texto` + `---` colado embaixo** = Título H2 (texto gigante + `---` aparece separado).
- **`Linha em branco` + `---`** = **Linha Horizontal (`<hr>`)**! E o tema do Obsidian ( somado à nossa fonte com *ligatures* Fira Code!) desenha uma linha horizontal ou une os 3 tracinhos 
<truncated 180 bytes>
