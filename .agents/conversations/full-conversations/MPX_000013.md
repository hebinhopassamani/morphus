- `Object.keys(T)`

```ts
public getPkAsRoute(...pks: [Partial<T>] | (string | number)[]): string {
  // CASO 1: Você passou um OBJETO (ex: getPkAsRoute(userRole) ou getPkAsRoute({ userId, roleId }))
  if (pks.length === 1 && typeof pks[0] === 'object' && pks[0] !== null) {
    const entity = pks[0] as Partial<T>;
    return this.primaryKeys
      .map((key) => encodeURIComponent(String(entity[key] ?? '')))
      .join('/');
  }

  // CASO 2: Você passou VALORES SOLTOS (ex: getPkAsRoute('usr-999', 'rol-888', 'corp-777'))
  return (pks as (string | number)[])
    .map((pk) => encodeURIComponent(String(pk ?? '')))
    .join('/');
}
```

### Olha a mágica linha por linha:
1. **`...pks: [Partial<T>] | (string | number)[]`**:
   Em TypeScript, o `...pks` ( igual ao `params` do C#!) transforma tudo o que você passar dentro dos parênteses num array chamado `pks`.
   - Se você chamar `getPkAsRoute(userRole)`, o array `pks` tem 1 item que é um objeto: `[{ userId: '111', roleId: '222', corporationId: '333' }]`.
   - Se você chamar `getPkAsRoute('111', '222', '333')`, o array `pks` tem 3 strings: `['111', '222', '333']`.

2. **Quando entra no `if` (Caso 1 — Objeto)**:
   Ele olha para o `this.primaryKeys` (que já está na ordem certa `['userId', 'roleId', 'corporationId']`), busca o valor de cada chave dentro do objeto (`entity['userId']`, `entity['roleId']`, `entity['corporationId']`) e junta tudo com `.join('/')` → resultado: **`"111/222/333"`**!
   E se for uma entidade simples como `Corporation` (onde `this.primaryKeys` é `['id']`), ele pega `entity['id']` e retorna **`"111"`**!

3. **Quando vai pro `return` final (Caso 2 — Valores soltos)**:
   Ele simplesmente pega os valores que você passou por vírgula (`'111', '222', '333'`) e junta com `.join('/')` → resultado: **`"111/222/333"`**!

Não tem como falhar! Serve pra 1 PK (`id`), 2 PKs, 3 PKs ou 10 PKs! 🚀

Cara, esse assunto é **nível sênior absurdo**! O nome oficial no .NET / Entity Framework Core é **`ConcurrencyStamp`**!

E existem **duas formas** de fazer isso funcionar — deixa eu te mostrar as duas porque tem uma armadilha clássica que a gente já pode evitar de cara:

---

### Forma 1: Lock na hora de abrir a tela (Lock Pessimista)
É exatamente o que você descreveu:
1. O **Usuário A** clica em Editar → o sistema carimba um hash no `ConcurrencyStamp` (e quem pegou).
2. O **Usuário B** tenta mexer nele enquanto o Usuário A está com a tela aberta → toma um *"Denied: Este registro já está sendo modificado por outro usuário!"* na cara.
- **⚠️ A única pegadinha dessa forma:** imagina que o Usuário A abriu a tela de edição, o sistema travou o registro pra ele, e aí **caiu a internet dele** ou ele **fechou a aba do Chrome no X** sem clicar em "Salvar" nem "Cancelar"! O registro ficaria travado pra sempre no banco se não tiver uma data de expiração curta (tipo `LockedUntil = DateTime.UtcNow.AddMinutes(5)`).

---

### Forma 2: `ConcurrencyStamp` nativo do EF Core (Concorrência Otimista — `IsConcurrencyToken()`)
Essa é a que o próprio ASP.NET Identity e os grandes ERPs usam, e **nunca trava registro órfão se o usuário fechar a aba**:
1. Todo registro no banco nasce com um `ConcurrencyStamp = Guid.NewGuid().ToString()`.
2. O **Usuário A** e o **Usuário B** abrem a tela de edição ao mesmo tempo. Os dois recebem o registro com o mesmo selo: `ConcurrencyStamp = "abc-111"`.
3. O **Usuário A** salva primeiro! Na hora do `UPDATE`, o Backend confere: *"O `ConcurrencyStamp` no banco ainda é `abc-111`?"* Sim! Então ele salva as alterações do Usuário A e **gera um novo hash** no banco: `ConcurrencyStamp = "xyz-222"`.
4. Dois segundos depois, o **Usuário B** clica em Salvar (mandando o `ConcurrencyStamp = "abc-111"` antigo que estava na tela dele).
5. O Backend vê que no banco já mudou para `"xyz-222"` e **bloqueia na hora (HTTP 409 Conflict)**:
   > *"Ops! Este registro acabou de ser modificado por outro usuário. Recarregue a página para ver os dados atualizados antes de salvar!"*

---

E o melhor da **Forma 2** (ou de combinar as duas):
- No **Frontend**, basta a nossa interface mãe [`IMorphusEntity`](file:///c:/Projetos/Morphus/mpx-source/mpx-morphus/mpx-frontend/src/core/mpx-entities/morphus-entity.interface.ts) (e a [`IMorphusRelatedEntity`](file:///c:/Projetos/Morphus/mpx-source/mpx-morphus/mpx-frontend/src/core/mpx-entities/morphus-related-entity.interface.ts)) ter:

