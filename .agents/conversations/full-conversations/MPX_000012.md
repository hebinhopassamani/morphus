### 1. Como está ligado no Banco hoje (`Corporation ➔ Workspace ➔ Application ➔ Menu`)
Hoje no domínio:
- **`Corporation`** é o *Tenant* principal (`CorporationId` no JWT).
- **`Workspace`** pertence à `Corporation` (`Workspace.CorporationId`).
- **`MorphusApplication`** pertence ao `Workspace` (`MorphusApplication.WorkspaceId`).
- **`Menu`** pertence à `MorphusApplication` (`Menu.ApplicationId`).

Ou seja: o **Menu** já muda indiretamente quando muda o **Workspace**, porque cada Workspace tem as suas próprias **Applications** (e cada Application tem a sua árvore de Menus)!
*(Mas se no futuro você quiser que uma mesma Application tenha menus diferentes dependendo do Workspace, aí sim poderíamos ter um `WorkspaceId` opcional na tabela `Menu` — por enquanto, como `Application` já é filha de `Workspace`, `Menu -> Application -> Workspace` já separa tudo automaticamente).*

Cara, essa pergunta é **excelente** — e tem um fundo de verdade histórica, mas também muito exagero ("mito") quando aplicado ao que fazemos hoje. Vou te explicar exatamente o que acontece por baixo do capô do Angular:

### 1. O que é VERDADE (de onde surgiu essa fama)
No Angular clássico (com `Zone.js` e Change Detection padrão):
- Toda vez que você digita uma letra, clica num botão ou dá `focus`/`blur` num input, o Angular roda um ciclo de **Change Detection** no template para saber se o texto na tela mudou.
- Qualquer função chamada no HTML — seja `{{ validator.showErros(campo) }}` **ou** `@if (campo.hasError('required'))` (repare que `hasError()` **também é uma função!**) — é executada novamente naquele ciclo de verificação.
- O problema real acontecia quando o dev colocava **processamento pesado** dentro da função chamada no HTML (ex: varrer arrays grandes com `.filter().sort()`, criar objetos novos a cada chamada ou fazer cálculo complexo). Aí sim travava a tela!

### 2. Por que no caso de validação (`showErros` vs `@if (hasError)`) é praticamente MITO:
1. **`hasError()` no `@if` também é função**: Escrever `@if (control.hasError('required'))` ou `@else if (control.hasError('minlength'))` chama métodos internos do Angular (`hasError`) no mesmo ciclo de Change Detection! 3. **Angular moderno (Signals)**: Como estamos usando `signal()` no projeto todo, a árvore de componentes reage muito menos à toa do que no Angular 2/4/8 antigo de onde surgiu esse trauma.

**Resumo da ópera:**
- **Proibido no HTML**: Chamar função no template que faz loop grande, `.filter()` pesado, formatação complexa ou cria `new Object()` / `new Array()` toda hora (para isso usamos `computed()`).
- **Totalmente seguro no HTML**: `control.hasError(...)` ou `validator.showErros(control)`, porque só fazem leitura direta de propriedade/Map em memória! 😄👊
